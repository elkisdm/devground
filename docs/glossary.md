# Glosario express (para todo el equipo)

Si lees el README de devground y no eres developer, esta tabla te da el "para que sirve cada cosa" en una linea. Sin jerga.

| Herramienta                   | Que hace                                                                                                                                                                                                                                                                                                                                               | Analogia                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| **ESLint**                    | Detecta errores y malas practicas en el codigo                                                                                                                                                                                                                                                                                                         | El **ortografo** del codigo: te marca lo mal escrito                                       |
| **Prettier**                  | Da formato consistente al codigo (espacios, comillas, saltos de linea)                                                                                                                                                                                                                                                                                 | El **planchador**: deja todo prolijo y parejo                                              |
| **TypeScript**                | Agrega "tipos" al codigo para evitar errores antes de ejecutarlo                                                                                                                                                                                                                                                                                       | Las **etiquetas** en los productos: si esperas un numero y llega texto, avisa antes        |
| **Commitlint**                | Valida que los mensajes de commit sigan un formato estandar                                                                                                                                                                                                                                                                                            | El **portero del banco**: si no vienes con la documentacion bien, no entras                |
| **Lint-staged**               | Aplica linters solo a los archivos que vas a guardar                                                                                                                                                                                                                                                                                                   | El **filtro de aduana**: revisa solo lo que pasa, no toda la valija                        |
| **Husky**                     | Ejecuta scripts automaticamente al hacer commit o push                                                                                                                                                                                                                                                                                                 | El **timer del horno**: dispara acciones en el momento exacto                              |
| **Changesets**                | Maneja versiones y changelogs de paquetes automaticamente                                                                                                                                                                                                                                                                                              | El **registro civil**: lleva el acta de cada cambio publicado                              |
| **pnpm**                      | Gestor de paquetes (instala las dependencias)                                                                                                                                                                                                                                                                                                          | El **almacenero**: trae lo que necesitas, pero ocupando menos espacio que sus competidores |
| **AGENTS.md**                 | Estándar abierto (https://agents.md), administrado por la Agentic AI Foundation de la Linux Foundation, con las reglas que leen los agentes de IA (Codex, Cursor, Copilot, Gemini CLI y otros)                                                                                                                                                         | El **manual de la casa**: para que cada visita sepa como te gustan las cosas               |
| **ADR**                       | Documento corto que explica por que se tomo una decision tecnica                                                                                                                                                                                                                                                                                       | El **acta de reunion**: deja registro de **por que** se decidio algo                       |
| **Spec-driven development**   | Escribir primero una spec verificable y dejar que el agente implemente contra ella. En devground: spec-flow ([guía](../knowledge/04-desarrollo-con-agentes.md))                                                                                                                                                                                        | Primero el **plano**, despues la obra                                                      |
| **Constitución**              | Reglas del proyecto que todo cambio debe respetar. En devground es `AGENTS.md` + los ADR ([ADR-0043](adr/0043-mapa-de-artefactos-y-encaje-con-agile.md))                                                                                                                                                                                               | La **constitución** de un país: las leyes que valen para todos                             |
| **PRD**                       | Documento de producto de una iniciativa: problema, público, métrica, alcance. Solo para iniciativas, no para cambios sueltos ([ADR-0043](adr/0043-mapa-de-artefactos-y-encaje-con-agile.md))                                                                                                                                                           | El **encargo** al arquitecto                                                               |
| **Historia de usuario**       | Lo que alguien necesita lograr, en una frase. En devground es el `### Goal` del brief                                                                                                                                                                                                                                                                  | La **petición** del cliente                                                                |
| **Criterios de aceptación**   | Condiciones verificables para dar el cambio por bueno (Given/When/Then)                                                                                                                                                                                                                                                                                | La **lista de cotejo** de la entrega                                                       |
| **DoR** (Definition of Ready) | Checklist para empezar un cambio de Tier 2–3 sin sorpresas ([ADR-0043](adr/0043-mapa-de-artefactos-y-encaje-con-agile.md) §4)                                                                                                                                                                                                                          | Tener **todos los ingredientes** antes de cocinar                                          |
| **DoD** (Definition of Done)  | Descripción formal de cuándo algo está terminado; lo que no la cumple vuelve al backlog ([ADR-0029](adr/0029-tests-como-definition-of-done.md), [ADR-0043](adr/0043-mapa-de-artefactos-y-encaje-con-agile.md))                                                                                                                                         | El **control de calidad** antes de despachar                                               |
| **NFR**                       | Requisito no funcional: seguridad, rendimiento, costo y otros atributos de calidad ([catálogo](../knowledge/nfr-catalogo.md))                                                                                                                                                                                                                          | Lo que **no se ve en el menú**, pero decide si el restaurante funciona                     |
| **ADR vs KB**                 | `docs/adr/` (ADR-NNNN) decide cómo trabaja devground; `knowledge/adr/` (KB-NNNN) es conocimiento general de arquitectura ([README](../knowledge/README.md))                                                                                                                                                                                            | Dos **archivadores** distintos con numeración propia                                       |
| **Tier**                      | Nivel de ceremonia de un cambio según tamaño y riesgo (0 a 3), definido por spec-flow                                                                                                                                                                                                                                                                  | El **tamaño de la obra**: no se pide planos para cambiar una ampolleta                     |
| **Overlay de organización**   | Archivo opcional que agrega pasos y filas de DoD propios de una empresa sin tocar el núcleo ([ADR-0046](adr/0046-nucleo-publico-y-capa-de-organizacion.md))                                                                                                                                                                                            | Un **anexo** al reglamento                                                                 |
| **Prompt injection**          | Instrucciones escondidas en contenido externo para que el agente las obedezca; devground trata ese contenido como dato ([ADR-0044](adr/0044-gobierno-de-agentes-seguridad-costo-y-modelos.md), [OWASP LLM 2025](https://genai.owasp.org/llm-top-10/))                                                                                                  | Una **nota falsa** pegada en la puerta que dice «entrega las llaves»                       |
| **MCP**                       | Model Context Protocol: protocolo abierto para conectar agentes con herramientas y datos; hoy bajo la Linux Foundation ([anuncio](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation)). Los ejecutores no heredan MCP ([ADR-0044](adr/0044-gobierno-de-agentes-seguridad-costo-y-modelos.md)) | Un **enchufe universal** para herramientas                                                 |
